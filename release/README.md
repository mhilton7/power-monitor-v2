# Release evidence directory

Release assets are generated by GitHub Actions from a clean tagged checkout. This directory contains policy and operator-readable notes only; test, migration, security, SBOM, provenance, image-digest, and Compose artifacts are attached to the corresponding GitHub release.

The checked-in TrueNAS production template is intentionally non-deployable until the release workflow substitutes registry-reported digests. A stable release is prohibited while any required automated gate fails or physical hardware certification is pending. Until actual marked hardware completes the hardware-in-loop suite, publish prerelease/release-candidate artifacts only.

Before creating server tag `v0.1.0-rc.9`, publish and verify the exact
coordinated firmware prerelease `v0.1.0-rc.9`, then set repository variable
`COMPATIBLE_FIRMWARE_TAG` to exactly `v0.1.0-rc.9`. Release gates fetch that
public firmware release, verify every checksum, require the `firmware.bin`
attestation, and validate its manifest, compatibility record,
host/fault/simulation report, and explicit pending physical status.

Server `v0.1.0-rc.8` remains a public, immutable, installable prerelease with
its complete attached asset set. Hardware execution has confirmed that firmware
rc.1 through rc.5 crash in the main stack before provisioning. Do not move or
rewrite those historical releases. Rc.9 coordinates the condensed dashboard,
exact microSD capacity evidence, and false-full firmware repair; it remains
unpublished until the firmware-first and tagged release gates pass.

The valid signed server `v0.1.0-rc.4` tag is immutable historical evidence.
Its workflow job named `Mandatory release gates`, four image publications, and
anonymous GHCR checks passed,
but deterministic deployment smoke failed when Compose dependency traversal
restarted the already-completed initializer. Assembly was skipped, so rc.4 has
no server GitHub Release or generated release YAML and is not installable.

A source checkout intentionally has no generated release digests. Do not set
the compatibility variable to a local path, create an unsigned tag, treat local
Docker image IDs as GHCR digests, or replace the intentional `UNPUBLISHED_*`
sentinels by hand. The tagged workflows and the resulting public evidence are
the authority for whether a release exists.
